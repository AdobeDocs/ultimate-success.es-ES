# Sitios rápidos y editables con editor universal y marcos modernos de SSR

Los equipos web modernos querían la libertad de los marcos de JavaScript modernos y sin encabezado sin sacrificar la edición en contexto para los especialistas en marketing. En esta sesión, mostramos cómo el Editor universal de Adobe Experience Manager y los marcos modernos de procesamiento del lado del servidor (SSR) (como las configuraciones de estilo React y Next.js) entregaban sitios rápidos optimizados para motores de búsqueda (SEO) que los autores aún podían editar visualmente. Explicamos cómo conectar Universal Editor a aplicaciones basadas en módulos, cómo la SSR afectaba al rendimiento y a Core Web Vitals, y cómo estructurar componentes para que los autores pudieran actualizar experiencias de forma segura sin dañar el front-end. Si estaba planificando o modernizando un proyecto de Adobe Experience Manager (AEM) o Edge Delivery Services (EDS), este seminario web le ofrece un modelo práctico que puede utilizar inmediatamente.

>[!VIDEO](https://video.tv.adobe.com/v/3491408/?learn=on&enablevpops)

## Principales conclusiones

* **Cuándo usar un sitio EDS estándar y cuándo un marco SSR personalizado**
Entendimos por qué un sitio estándar de Adobe Experience Manager Edge Delivery Services (EDS) era el mejor predeterminado para la mayoría de los proyectos y cuándo tenía sentido colocar el editor universal en una aplicación existente (como una tienda o portal) en lugar de reconstruirla.

* **Cómo se conectó el editor universal a EDS y a los marcos existentes**
Vimos cómo el editor universal encajaba en una configuración típica de AEM EDS y cómo se aplicaban los mismos conceptos al conectarlo a una aplicación SSR de estilo React o Next.js que ya estaba en producción.

* **SSR donde se contabilizó el equilibrio entre los valores predeterminados de EDS y las necesidades de rendimiento y SEO**
Aprendimos cuándo podíamos confiar en los valores predeterminados de EDS y cuándo realmente necesitábamos el procesamiento personalizado del lado del servidor (SSR) para experiencias específicas, incluido el impacto en la SEO y Core Web Vitals para páginas de alto valor como detalles del producto o páginas de aterrizaje.

* **Creación que no ha roto los patrones de la aplicación para desarrolladores y especialistas en marketing**
Descubrimos patrones de modelos de componentes y contenido que permitían a los desarrolladores mantener una base de código limpia y mantenible, a la vez que ofrecían a los autores un poder de edición en contexto seguro, ya fuera en un sitio EDS estándar o integrado con un marco de trabajo existente.
